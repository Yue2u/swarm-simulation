# 1. Основа: что это за проект и как он устроен

## 1.1. Идея

Мы моделируем **стаю** — множество простых объектов (агентов), у каждого из которых нет
«начальника» и общего плана. Каждый агент видит только соседей вокруг себя и по трём простым
правилам решает, куда лететь. Из этих локальных правил возникает сложное коллективное
поведение: стая собирается в одно облако, летит в одном направлении, огибает препятствия.

Два мира для наглядности:

* **Рыбы** — маленький мир (пруд/риф) 320 × 140 × 320 м, радиус обзора 3.5 м, скорость до 14 м/с.
* **Птицы** — большой мир 1200 × 440 × 1200 м, радиус обзора 14 м, скорость до 32 м/с.

Правила одни и те же, отличаются только параметры мира.

## 1.2. Стек технологий

| Технология | Зачем |
|---|---|
| **Rust** | Язык проекта. Быстрый, безопасный по памяти, без сборщика мусора |
| **wgpu** | Слой над видеокартой (Vulkan / Metal / D3D12 / OpenGL / WebGPU) |
| **WGSL** | Язык шейдеров (программ для GPU) |
| **winit** | Создание окна и обработка ввода |
| **glam** | Векторная и матричная математика (`Vec3`, `Mat4`) |
| **bytemuck** | Безопасная передача структур в память GPU |

Главная идея: **всё, что можно, делается на GPU**. Видеокарта умеет выполнять тысячи
простейших операций одновременно. У нас 100 000 агентов, и для каждого нужно найти соседей и
посчитать силы — это идеальная задача для параллельной обработки.

## 1.3. Пять крейтов (модулей)

Проект разбит на 5 библиотек, каждая со своей ответственностью:

| Крейт | Роль |
|---|---|
| `boids-core` | «Мозг» без GPU: структуры данных, конфиг мира, CPU-эталон симуляции, тесты. Не зависит от wgpu |
| `boids-gpu` | Compute-часть: буферы, shader-пайплайны, шаги симуляции на видеокарте |
| `boids-scene` | Общая сцена: камера, свет, параметры материалов, процедурные меши |
| `boids-render` | Графическая часть: проходы рендера (небо, рельеф, океан, агенты, постобработка) |
| `boids-app` | Приложение: окно, ввод, главный цикл, скриншоты, бенчмарк |

Почему так: `boids-core` можно тестировать **без видеокарты**, а `boids-gpu` сверить с
`boids-core` — это и есть способ проверять, что шейдеры считают то же самое, что и «эталон».

## 1.4. Что такое compute-шейдер (простым языком)

Обычный шейдер запускается для каждого пикселя картинки. **Compute-шейдер** — программа
общего назначения: мы говорим GPU «запусти 100 000 копий этой функции», и каждая копия
обрабатывает одного агента. Все копии работают параллельно.

Память GPU делится на буферы. Мы держим **два буфера агентов** (`boid_src` и `boid_dst`) и
каждый кадр читаем из одного, а пишем в другой, потом меняем их местами (это называется
*ping-pong*, «пинг-понг»). Так никто не читает данные, которые в этот же момент меняет сосед.

## 1.5. Конвейер кадра

Каждый кадр выполняется цепочка проходов. Сначала — **симуляция**:

1. `clear_cells` — очистить таблицу пространственных ячеек.
2. `hash` — разложить агентов по ячейкам сетки (записать «ключ ячейки + номер агента»).
3. `sort_step` ×153 — отсортировать ключи битонной сортировкой, чтобы агенты одной ячейки лежали рядом.
4. `build_ranges` — для каждой ячейки запомнить, где начинается и кончается её кусок массива.
5. `integrate` — для каждого агента найти 27 соседних ячеек, сложить силы, обновить скорость и позицию.

Затем — **рендер**:

6. Небо / атмосфера (фон).
7. Рельеф (мир птиц) или океан-raymarching (мир рыб).
8. Деревья (мир птиц).
9. Агенты (одним instanced-вызовом).
10. Bloom — свечение ярких участков.
11. Композит — тонмаппинг (ACES), хроматическая аберрация, виньетка, зерно → экран.

Порядок важен: рельеф рисуется **после** неба (перекрывает его), агенты — **после** рельефа
(прячутся за холмами), а постобработка — в самом конце.

## 1.6. CPU против GPU: кто что делает

| Работа | Где выполняется |
|---|---|
| Поиск соседей, силы, движение 100k агентов | **GPU** (compute) |
| Сортировка ключей сетки | **GPU** (compute) |
| Генерация мешей агентов и рельефа | **GPU** (vertex shader, процедурно, без vertex buffer) |
| Меш дерева (один раз) и его scatter | CPU строит меш, GPU рассыпает и рисует |
| Отрисовка | **GPU** |
| Создание окна, ввод, запуск проходов | CPU |
| Скриншоты, бенчмарк | CPU (вызывает GPU) |
| Проверка «GPU считает как эталон» | CPU-эталон в тестах |

CPU **не перебирает** агентов в цикле — он только отдаёт команды. Поэтому 100 000 агентов
не «вешают» процессор.

## 1.7. Мир и окружение

* Мир задан числами (`SimConfig`): размеры коробки, радиус обзора, скорости, веса сил.
* Рельеф и риф — **процедурные**: не картинка и не готовая модель, а математическая функция
  от координат (`height_at`, `reef_field`). Одна и та же формула используется и для отрисовки,
  и для столкновений — поэтому птица не пролетает сквозь нарисованный холм.
* Освещение — **аналитическое**: небо считается по формуле рассеяния света в воздухе
  (подробнее в `02-matematika.md`), а не печётся заранее.

## 1.8. Что здесь «3D-моделирование»

* процедурная генерация геометрии (рельеф, деревья, тела агентов) в коде;
* работа с матрицами камеры, проекцией, нормалями, освещением;
* уровни детализации и оптимизация (LOD, half-res, culling);
* правильная намотка треугольников и отсечение задних граней;
* материалы: albedo, нормали, свечение, туман/перспектива;
* постобработка изображения.

## 1.9. Честность измерений

Локально проект тестировался на **встроенной графике** (AMD Radeon через WSL). Реальные
замеры FPS на целевой карте (RTX 4060 Ti) не делались — об этом прямо написано в
`docs/perf.md`. Числа бенчмарка — это «форма затрат» (какой проход сколько стоит), а не
обещание конкретного FPS.

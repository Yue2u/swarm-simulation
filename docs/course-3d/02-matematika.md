# 2. Математика проекта

Здесь собрана вся математика, которая реально используется в коде. Формулы даны в том виде, в
каком они записаны в шейдерах (`shaders/`) и в CPU-эталоне (`crates/boids-core/src/reference.rs`).

---

## 2.1. Базовые векторы

Позиция и скорость агента — это трёхмерные векторы `Vec3`.

| Операция | Формула | Зачем |
|---|---|---|
| Длина | `|v| = sqrt(vx² + vy² + vz²)` | расстояние, скорость |
| Нормализация | `v̂ = v / |v|` | направление без длины |
| Скалярное произведение | `a·b = ax·bx + ay·by + az·bz` | угол, проекция, освещение |
| Векторное произведение | `a×b` | перпендикуляр, построение базиса |
| Расстояние между точками | `|a − b|` | поиск соседей |

Угол между векторами: `cos θ = (a·b) / (|a|·|b|)`.

Из этого строится **базис ориентации** агента (локальные оси «вперёд / вправо / вверх»):

```
fwd   = normalize(vel)                       // нос по направлению движения
right = normalize(cross(reference, fwd))     // reference — мировая ось
up    = cross(fwd, right)                    // третья ось перпендикулярна первым двум
```

Матрица `M` из этих трёх осей поворачивает модель агента в мировые координаты:
`world = pos + M · local`.

## 2.2. Три правила Бойдса (силы)

Каждый агент считает три силы по своим соседям (соседи — те, кто ближе `r_percept`):

**Разделение (separation)** — отталкиваться от слишком близких:

```
F_sep = Σ  (p_self − p_other) / |p_self − p_other|²
```

Сумма по соседям ближе `r_sep` (у нас `r_sep = 0.35 · r_percept`). Деление на квадрат
расстояния даёт закон `1/r`: чем ближе сосед, тем сильнее отталкивание.

**Выравнивание (alignment)** — лететь в среднем направлении соседей:

```
F_ali = normalize(Σ v_other) · v_max − v_self
```

**Сплочённость (cohesion)** — тянуться к центру масс соседей:

```
center = (Σ p_other) / N
F_coh  = normalize(center − p_self) · v_max − v_self
```

Запись `желаемая_скорость − текущая_скорость` называется **steering** (рулевое управление) по
Рейнольдсу. Это важно: если просто складывать векторы смещения, при сжатии стаи сила растёт до
бесконечности и стая «взрывается». Форма «желаемое минус текущее» ограничена скоростью `v_max`
и поэтому устойчива.

Итоговая сила: `F = w_sep·F_sep + w_ali·F_ali + w_coh·F_coh` (с дополнительными весами, см. ниже).

## 2.3. Адаптивные веса (главная «фишка» устойчивости)

Стая должна сама поддерживать нужную плотность. Введём **плотность** как долю от эталонной:

```
density = N_соседей / density_ref          (density_ref = 30)
push    = density ^ density_gain           (density_gain = 1)
w_sep_eff = w_sep · push
w_coh_eff = w_coh / push
```

Смысл:

* `density = 1` — эталонная плотность, веса равны номинальным (точка равновесия);
* плотнее эталона (`push > 1`) — сильнее расталкиваемся, слабее притягиваемся;
* реже эталона (`push < 1`) — наоборот, притягиваемся сильнее.

Раньше использовалась пара `w_sep·(1+density)` и `w_coh·exp(−density)`. Она была примерно в
10 раз «расталкивающей» уже при эталонной плотности, и стая, родившаяся с такой плотностью,
разлеталась. Новая формула **симметрична** относительно `density_ref`, поэтому старт — это
равновесие, а не «заряд на взрыв».

Почему именно 30? Стая — это граф, где рёбра — «вижу соседа». Такой случайный геометрический
граф связен, только пока средняя степень (число соседей) больше примерно `ln(N)`. При
`N = 100 000` это `ln(100000) ≈ 11.5`. Старое значение 12 стояло ровно на пороге, и стая
рассыпалась на мелкие группы; 30 даёт запас.

## 2.4. Интеграция движения (как из силы получается позиция)

Используется метод **полунеявного Эйлера** (самый простой численный интегратор):

```
a  = F / m                  (масса m = 1, поэтому a = F)
v' = v + a · dt             // обновляем скорость
v' = v' · exp(−drag · dt)   // сопротивление среды (вода/воздух)
v' = clamp(|v'|, v_min, v_max)   // ограничение скорости
p' = p + v' · dt            // обновляем позицию
```

`dt` — шаг времени (1/60 секунды). Сила ограничивается `max_force`, скорость — диапазоном
`[min_speed, max_speed]`. Ограничение `min_speed` нужно, чтобы агент не мог «зависнуть» на месте.

Порядок вычислений зафиксирован и одинаков на CPU и GPU — иначе две реализации разойдутся.

## 2.5. SDF: расстояние до поверхности

**SDF (signed distance field)** — функция, которая по точке пространства возвращает расстояние
до ближайшей поверхности. Знак говорит, где мы: **минус — внутри**, **плюс — снаружи**.

Простейшие примеры:

```
сфера:   d(p) = |p − center| − radius
плоскость: d(p) = p.y − height
коробка: d(p) = |p − center| − half   (покоординатно, затем max с нулём и длина)
```

Риф — это набор «колонн», которые повторяются по сетке ячеек (`reef_field`), а рельеф — это
`d(p) = p.y − height_at(p.xz)`. Плавное объединение двух SDF делается через `smin` (smooth min),
чтобы не было острых швов.

**Градиент** SDF даёт нормаль поверхности (направление «наружу»). Считаем центральными разностями:

```
∇d(p) ≈ ( d(p+e_x) − d(p−e_x),  d(p+e_y) − d(p−e_y),  d(p+e_z) − d(p−e_z) ) / (2·eps)
```

где `eps` — половина размера ячейки.

**Сила избегания** препятствия:

```
F_avoid = normal · smoothstep(r_safe, 0, d) · strength
```

`smoothstep` плавно включает силу по мере приближения и **насыщается** (не растёт до
бесконечности), поэтому агент не «выстреливает» при касании.

## 2.6. Процедурный шум (рельеф и биомы)

Рельеф — не текстура, а сумма шума («фрактальный броуновский шум», fBm):

1. **Value noise**: в целочисленных узлах решётки берём псевдослучайные числа (хэш), между ними
   плавно интерполируем многочленом Эрмита `w = f²·(3 − 2f)`.
2. **Четыре октавы**: складываем шум на частотах `f, 2f, 4f, 8f` с амплитудами `1, ½, ¼, ⅛`.
   Мелкие октавы добавляют детали, крупные — форму.
3. **Domain warping**: перед выборкой шума координату сдвигаем другим шумом. Это превращает
   «шишки» в хребты и долины.

Формула высоты: `height(p) = fbm(p) · amplitude`.

**Биомы** (лес / дюны / каньон) — это **разбиение единицы**: три веса, которые в сумме дают 1.
Поэтому переход между биомами плавный, а не резкая линия. Высоты, цвет и растительность
смешиваются этими весами.

## 2.7. Атмосфера и небо

Небо считается по упрощённой модели **однократного рассеяния света**:

* два типа частиц: **Рэлей** (молекулы воздуха, голубые, высота 8 км) и **Ми** (аэрозоль,
  серый, рассеивает вперёд, высота 1.2 км);
* **оптическая толщина** вдоль луча: `τ = β_R·H_R·m + β_M·H_M·m`, где `m = 1/max(dir.y, ε)` —
  «воздушная масса», во сколько раз наклонный путь длиннее вертикального;
* **закон Бугера–Ламберта–Бера**: `T = exp(−τ)` — доля света, дошедшая без рассеяния;
* цвет, рассеянный в камеру: `L = I_sun · exp(−τ_sun) · (β_R·P_R + β_M·P_M) / (β_R+β_M) · (1 − exp(−τ))`;
* фазовые функции: `P_R(θ) = (3/16π)(1 + cos²θ)` и Хеньи–Гринстейна для Ми (вытянута вперёд,
  даёт ореол вокруг солнца).

Из этой модели сами собой получаются закат (солнце красное, потому что его свет прошёл много
воздуха) и бледный горизонт (там путь самый длинный).

## 2.8. Камера и лучи

Камера — орбитальная: смотрит на центр мира с расстояния, вращается по сфере.

* 3D-точка → экран: умножение на матрицу «вид × проекция» → **NDC** (координаты в `[−1, 1]`);
* экран → 3D-луч: обратное преобразование даёт начало луча (позиция камеры) и направление;
* курсор взаимодействует со стаей: луч пересекаем с плоскостью, строим точку фокуса, и агенты
  либо притягиваются к ней, либо отталкиваются (с закруткой).

Пересечение луча с горизонтальной плоскостью `y = h`:

```
t = (h − origin.y) / dir.y      (если dir.y ≈ 0 — пересечения нет)
```

## 2.9. Цвет и тонмаппинг

Рендер идёт в **линейном HDR** (значения яркости могут быть больше 1). Чтобы показать картинку
на экране, нужен тонмаппинг — сжатие диапазона в `[0, 1]`. Используется кривая **ACES**
(Нарковича):

```
x' = (x·(2.51x + 0.03)) / (x·(2.43x + 0.59) + 0.14)
```

Она сохраняет оттенок в ярких местах (в отличие от простой `x/(1+x)`, которая уводит всё в
белый). Порядок постобработки: аберрация → экспозиция + bloom → ACES → виньетка, грейд, зерно.
Яркость (luma) для bloom считается по Rec. 709: `0.2126R + 0.7152G + 0.0722B`.

## 2.10. Что ещё используется

| Понятие | Формула / смысл |
|---|---|
| Центроид | среднее арифметическое позиций |
| Порядок параметра (order parameter) | `|Σ v̂| / N` — насколько стая выровнена (0..1) |
| Интерполяция (mix/lerp) | `a + (b − a)·t` — морфинг, смешивание биомов и цветов |
| smoothstep | плавный переход `0→1` на отрезке |
| clamp | ограничение значения диапазоном |
| Экспонента `exp(−drag·dt)` | физически корректное затухание скорости |

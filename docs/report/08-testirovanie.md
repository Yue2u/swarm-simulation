# 8. Тестирование и валидация

## 8.1. Три уровня проверок

Проект покрыт тестами трёх видов:

* **CPU-юнит-тесты** (`cargo test --workspace`) — раскладка структур, математика, камера, поля SDF
  и рельефа, генераторы мешей. Работают без видеокарты.
* **GPU-набор** (`crates/boids-gpu/tests/gpu`) — отдельный бинарник на одном устройстве: компиляция
  шейдеров, совпадение раскладки Rust/WGSL, сверка симуляции с CPU-эталоном, сортировка, сетка.
* **Render-набор** (`crates/boids-render/tests/render_suite`) — рисует кадры в off-screen таргет и
  читает пиксели и глубину: доказательства, что «картинка» не разъехалась с «физикой».

Почему GPU-наборы — бинарники с `harness = false`, а не `#[test]`: `libtest` запускает каждый тест в
своём потоке, а создание и уничтожение GL-устройства `wgpu` вне главного потока роняет процесс на
выходе; к тому же одно устройство обслуживает весь прогон, что дешевле.

## 8.3. Самые показательные проверки

| Проверка | Что доказывает |
|---|---|
| `layout/wgsl_offsets_match_rust` | смещение поля в WGSL совпадает с Rust (иначе симуляция незаметно неверна) |
| `layout/struct_sizes_are_exact` | структура не выросла за размер, который предполагает её WGSL-зеркало |
| `shaders/compile_all` | шейдер компилируется на тесте, а не падает в рантайме |
| `reference/one_step_matches_cpu` | шейдер считает шаг ровно как CPU-эталон, агент за агентом |
| `reference/many_steps_match_cpu_aggregates` | систематический дрейф, который поштучная сверка пропустила бы |
| `reference/spawned_flock_stays_one_group` | стая остаётся одной после сотен шагов |
| `spawn/spawn_graph_is_connected_at_scale` | граф обзора 100k стаи связен (нет распада на группы) |
| `grid/matches_naive` | сетка находит ровно тех же соседей, что и честный перебор |
| `grid/long_run_matches_naive` | сетка не теряет соседей со временем |
| `sort/immediates_reach_the_shader` | параметры стадии сортировки реально меняются от прохода к проходу |
| `sdf/wgsl_matches_rust` | формула поля одинакова на CPU и GPU (`|Δ| < 1e-4`) |
| `render/terrain_grounds_the_sky_world` | рельеф непрозрачный (намотка треугольников верна) |
| `render/landmark_is_drawn` | замок реально доходит до экрана (binding 9, инстансы, пиксели) |
| `render/ocean_writes_depth` | raymarch пишет корректную глубину, рыбы перекрываются рифом |
| `render/underwater_is_blue_and_lit` | вода рассеивает свет и поглощает по каналам |
| `render/bloom_adds_light` | bloom-пирамида добавляет свет, а не отбрасывает яркое |
| `render/focus_marker_is_visible` | точка фокуса курсора доходит до шейдера и перекрывается окружением |

## 8.4. Дефекты, которые тесты уже поймали

Тесты в этом проекте не формальность — они ловили реальные ошибки:

* **рассинхрон раскладки** Rust/WGSL не падал и почти не виден в диффе — его держит device-тест;
* **половина треугольников рельефа** имела обратную намотку и отсекалась: земля просвечивала сеткой.
  Закрыто тестом `render/terrain_grounds_the_sky_world`;
* **стая распадалась** на мелкие группы из-за «заряжённого» спавна и асимметричных весов — закрыто
  `spawn/*` и `reference/spawned_flock_stays_one_group`;
* **стены замка рисовались с двух сторон** из-за знака в `push_box` — закрыто
  `push_box_closes_on_all_six_sides`;
* **sky-проверка ловила центр кадра**, который теперь закрыт замком, — проверку перевели на столбец
  со смещением от центра, чтобы она снова тестировала шейдер, а не замок.

## 8.5. Как запускать

```bash
cargo test --workspace                 # CPU-тесты, GPU-набор и render-набор
cargo test -p boids-gpu  --test gpu -- --list
cargo test -p boids-render --test render_suite
BOIDS_TEST_REQUIRE_GPU=1 cargo test --workspace   # падать, а не брать программный адаптер
```

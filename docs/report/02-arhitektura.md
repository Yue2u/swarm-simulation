# 2. Архитектура проекта

## 2.1. Пять крейтов

Проект разбит на 5 библиотек, каждая со своей ответственностью:

| Крейт | Роль |
|---|---|
| `boids-core` | «Мозг» без GPU: структуры данных, конфиг мира, CPU-эталон симуляции, камера и лучи, поля SDF/рельефа, загрузчик WGSL. **Не зависит от wgpu** |
| `boids-gpu` | Compute-часть: устройство, буферы, shader-пайплайны, шаги симуляции на видеокарте |
| `boids-scene` | Процедурный арт-контент: вода и пост-параметры, атмосфера, рельеф, деревья, замок |
| `boids-render` | Графическая часть: граф кадров и проходы (небо, рельеф, океан, агенты, постобработка), вьюер моделей |
| `boids-app` | Приложение: окно, ввод, главный цикл, скриншоты, бенчмарк |

Почему так: `boids-core` можно тестировать **без видеокарты**, а `boids-gpu` сверить с
`boids-core` — это и есть способ проверять, что шейдеры считают то же самое, что и «эталон».

## 2.2. Конвейер кадра

Каждый кадр выполняется цепочка проходов. Сначала — **симуляция** (compute):

1. `clear_cells` — очистить таблицу пространственных ячеек.
2. `hash` — разложить агентов по ячейкам сетки (записать «ключ ячейки + номер агента»).
3. `sort_step` ×153 — отсортировать ключи битонной сортировкой, чтобы агенты одной ячейки лежали рядом.
4. `build_ranges` — для каждой ячейки запомнить, где начинается и кончается её кусок массива.
5. `integrate` — для каждого агента найти 27 соседних ячеек, сложить силы, обновить скорость и позицию.

Затем — **рендер**:

6. Небо / атмосфера (фон).
7. Рельеф (мир птиц) или океан через raymarching (мир рыб).
8. Деревья (мир птиц) и замок-ориентир.
9. Агенты (одним instanced-вызовом).
10. Bloom — свечение ярких участков.
11. Композит — тонмаппинг (ACES), хроматическая аберрация, виньетка, зерно → экран.

Порядок важен: рельеф рисуется **после** неба (перекрывает его), агенты — **после** рельефа
(прячутся за холмами), а постобработка — в самом конце.

## 2.3. CPU против GPU: кто что делает

| Работа | Где выполняется |
|---|---|
| Поиск соседей, силы, движение 100k агентов | **GPU** (compute) |
| Сортировка ключей сетки | **GPU** (compute) |
| Генерация мешей агентов и рельефа | **GPU** (vertex shader, процедурно, без vertex buffer) |
| Меш дерева и замка (один раз) | CPU строит меш, GPU рассыпает/рисует instanced |
| Отрисовка | **GPU** |
| Создание окна, ввод, запуск проходов | CPU |
| Скриншоты, бенчмарк | CPU (вызывает GPU) |
| Проверка «GPU считает как эталон» | CPU-эталон в тестах |

CPU **не перебирает** агентов в цикле — он только отдаёт команды. Поэтому 100 000 агентов не
«вешают» процессор.

## 2.4. Память и выравнивание

Все буферные структуры кратны 16 байтам: `vec3<f32>` в WGSL имеет выравнивание 16, поэтому в Rust
никогда не ставится `[f32; 3]` без соседнего скаляра, закрывающего дырку.

| Rust | Размер | WGSL | Примечание |
|---|---|---|---|
| `Boid` | 48 B | `struct Boid` | pos+species, vel+phase, prev_dir+color_seed |
| `KeyVal` | 8 B | `struct KeyVal` | только u32: ключ ячейки + индекс агента |
| `SimParams` | 144 B | `struct SimParams` | веса, скорости, границы, режим |
| `InteractionUniforms` | 48 B | `struct Interaction` | луч курсора, точка фокуса, режим |
| `SortParams` | 16 B | `struct SortParams` | j, k, n, pad |

Домен ограничен `bounds_half`, сетка выводится из него и `r_percept`. Размер ячейки равен
`r_percept` — это требование корректности 27-ячеечного поиска, а не тюнинг. Пустая ячейка помечена
`U32_MAX`. Агентные буферы — **ping-pong**: каждый кадр читаем из одного, пишем в другой, затем
меняем местами, чтобы никто не читал данные, которые в этот же момент меняет сосед.

Отдельный device-тест `layout/wgsl_offsets_match_rust` сверяет смещения полей в WGSL с Rust
`offset_of!`. Это, пожалуй, самая ценная проверка в проекте: рассинхрон раскладки не падает и почти
не виден в диффе — симуляция просто незаметно ведёт себя неправильно.

## 2.5. Два мира

| Параметр | Рыбы (подводный) | Птицы (небо) |
|---|---|---|
| Размер мира | 320 × 140 × 320 м | 1200 × 440 × 1200 м |
| Радиус обзора `r_percept` | 3.5 м | 14 м |
| Макс. скорость | 14 м/с | 32 м/с |
| Сетка (при 100k) | 91 × 40 × 91 = 331 240 | 86 × 31 × 86 = 229 276 |
| Окружение | sphere tracing рифа, Beer-Lambert, каустика, god rays | heightfield, 3 биома, атмосфера Rayleigh+Mie, деревья |
| Меш агента | тело + хвост, светится (биолюминесценция) | тело + машущие крылья, без свечения |

Все ресурсы обоих миров создаются на старте, поэтому переключение по `TAB` — это смена активного
pipeline без пересоздания устройства или поверхности.

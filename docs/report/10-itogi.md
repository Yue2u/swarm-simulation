# 10. Итоги и дальнейшая работа

## 10.1. Что получилось

За четыре этапа собран цельный интерактивный проект:

* полностью GPU-резидентная симуляция стаи: ping-pong буферы, пространственная сетка, битонная
  сортировка, интегрирование сил — CPU не перебирает агентов;
* два процедурных мира с общим кодом и разными параметрами: биолюминесцентный подводный риф
  (raymarching, поглощение по каналам, каустика, god rays) и небесный ландшафт (heightfield, три
  биома, деревья, аналитическая атмосфера);
* интерактив курсором-лучом (аттрактор / репеллер с закруткой), огибание препятствий через SDF;
* HDR-конвейер с bloom и ACES-тонмаппингом, хроматическая аберрация, виньетка, зерно;
* морфинг агентов между мирами за 1.5 с по `TAB` без пересоздания устройства;
* процедурный замок-ориентир с семью материалами, экспортируемый в OBJ;
* headless-скриншоты, бенчмарк по проходам и 139 автотестов трёх уровней;
* подробная документация (README, architecture, gpu-pipeline, math, perf, пять ADR) и материалы к
  защите.

## 10.2. Чего ещё нет

* **Окружение не морфится**, морфятся только агенты: океан и небо — разная геометрия на разных
  масштабах, поэтому фон меняется в кадр нажатия, а кросс-фейдятся только тела.
* **Отдельного теста «птица не проходит сквозь нарисованный склон»** нет; поле и меш теперь считаются
  из одного выражения — это и есть свойство, которое делает утверждение истинным.
* **Radix-сортировка** вместо 153-стадийной битонной — отложена (ADR-0003) до упора в бюджет на
  целевом железе.
* **Замеры на целевом железе** (RTX 4060 Ti, Vulkan) — самый важный недостающий пункт.

## 10.3. Возможные направления развития

1. **Radix sort** для сортировки ключей сетки — при 100k сортировка занимает заметную долю кадра.
2. **Морфинг окружения** — рендер обоих миров и смешивание, если это оправдано по стоимости.
3. **Коллизии птиц с рельефом** — силовая часть уже есть; нужен явный тест на «не проходит сквозь».
4. **egui-оверлей** для тюнинга весов в рантайме — при желании показывать настройку вживую.
5. **Детерминированный режим** (фиксированный сид и `dt`) для скриншот-регрессий.
6. **Экспорт сцены** (glTF) вместе с замком, если понадобится переносить контент в другой движок.

## 10.4. Заключение

Проект показывает, что даже сложное коллективное поведение 100 000 объектов можно целиком уместить
на видеокарте, оставив процессору только управление: поиск соседей, сортировку и силы считают
шейдеры. Процедурная генерация (рельеф, риф, деревья, замок) даёт «бесконечный» мир без
предварительно запечённых ассетов, а многоуровневая система тестов удерживает картинку и физику
вместе. Отдельная гордость — процедурный замок: собранный из примитивов, но с настоящей
архитектурной детализацией и выгрузкой в стандартный 3D-формат.
